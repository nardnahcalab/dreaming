01 · system design

The three flows

Everything the system does is one of three currents. Prompt / response carries user and agent messages from the four tools down into memory. Information is the distilled context packed into the model call and the extraction it returns. Intelligence moves curated memories back out to the tools that need them. Arrows only ever point down — nothing writes upward into a higher-trust layer.

02 · memory model

Two layers, one direction

Modeled on how biological memory separates fast episodic encoding from slow consolidation — and on Anthropic's 2026 "Dreams" architecture: the input store is never modified, so every consolidation is reversible. Zhang et al. (arXiv:2605.12978) showed in-place rewriting degrades memory through misgrouping, interference and overfit; this design makes that class of failure structurally impossible.

03 · the dreaming pass

Dreamer.dream() — 10 steps on loop

One consolidation pass. Watch the highlight travel: it's the exact order the code executes, including both early-exit guards and the LLM→heuristic fallback.

01Load episodic sessionsread-only, sorted chronologically
02Compute `already` setunion across every dream — never reprocess
03Diff → new sessions, take batchlast N unseen (default 40)
04Empty batch?→ log dream_skipped, return (no empty artifact)
05Build promptprior memory + transcripts, budgeted to ~120K chars
06Call local OllamaJSON mode, temp 0.2, 900s timeout
07Any exception?→ record llm_error, fall back to regex heuristic
08Validate & clampcategories forced to the fixed 5-way taxonomy
09Dedup + importance cap“plan to forget” — crystallized only
10Save NEW artifact + repointimmutable dream-NNNN, then log to history

Why this loop is safe

  • Union across all dreams — a session in dream-0001 can't be re-dreamed by dream-0003 even if dream-0002 ignored it.
  • Early exit — nothing new ⇒ nothing written. No vacuous artifacts polluting history.
  • Graceful degradation — timeout, bad JSON or no Ollama still yields a completed dream via heuristics.
  • Prompt budget — adaptive split of 120K chars fixed a real 456K-char timeout (runlog §8).
  • Forget selectively — importance cap shrinks layer 2; layer 1 is never touched.
  • Traceable — every entry keeps sources[] back to raw evidence.
04 · software components

Component reference

Every module, its role in the three flows, and what's inside. Colored tags show which current the component primarily carries.

schema.pycontract

The shared vocabulary. Collectors produce these types, stores serialize them, the dreamer consumes them — so no downstream code ever knows which tool a session came from.

  • Message — role, content, timestamp, meta
  • Session — content_hash (SHA-256/24), transcript_text() with 3K/60K clipping
  • MemoryEntry — category, importance, confidence, sources[]
  • DreamArtifact — entries + stats + previous_dream chain
  • from_dict() drops unknown keys → old dreams stay loadable
collectors.pyprompt / response

Four collectors, one interface: available() + collect(limit) → List[Session].

  • OpenCodeCollector — session_v2 ⨝ session_message, JSON content parts
  • ClaudeCodeCollector — skips /subagents/ and system-reminders
  • CodexCollector — response_item preferred, event_msg fallback w/ dedup
  • HermesCollector — sessions ⨝ messages, cwd → project
  • _clean() drops tool_use/tool_result noise · _iso() unifies s/ms/µs/ISO
  • SQLite opened mode=ro · JSONL errors="replace"
episodic.pyprompt / response

EpisodicStore — safety principle #1 made concrete.

  • add() — existence check → open(path,"x") exclusive create
  • index.json — metadata only, atomic tmp + os.replace
  • known_hashes() — fast pre-filter so re-sync costs ~0.1s
  • all_sessions() — chronological load for the dreamer
  • ingest_log.jsonl — stored / skip_duplicate audit trail
dreaming.pyinformation

The engine — five parts, largest module.

  • LocalLLM — stdlib urllib Ollama client, JSON mode, 900s timeout
  • DREAM_SYSTEM — 5 categories, durability + specificity + anti-hallucination rules
  • _build_dream_prompt() — adaptive 120K char budget across batch
  • heuristic_consolidate() — regex fallback, carries prior entries forward
  • DreamStore — immutable saves, pointer rollback, history log
  • Dreamer.dream() — the 10-step orchestration above
evaluator.pyintelligence

Safety principle #3 — compare before you trust.

  • compare(before, after) — kept / lost / added, retention %, category histograms
  • important_lost — any lost entry with importance ≥ 0.7 ⇒ degradation warning
  • run_self_test() — duplicates, vague entries (<4 words), health verdict
  • Measurable output: 100% retention dream-0001→0002
recall.pyintelligence

Two-layer retrieval — curated answer first, raw evidence beneath.

  • Crystallized — 1.0 × token-overlap + 0.3 × importance, threshold ≥ 0.15
  • Episodic — 0.6 × overlap over user and assistant messages
  • _tokenize() — lowercase, non-alnum split, len > 2
  • Pure stdlib — no TF-IDF, no embeddings, zero deps

06 · design principles

Four safety principles → four mechanisms

Taken from the reference research and enforced by construction, not by convention.

01

Preserve the input

Session files and dream artifacts both use exclusive-create. Sources open read-only. Nothing in layer 1 can be rewritten even by a bug.

✓ re-sync = 0 writes (runlog §6)
02

Instrument the loop

Every ingest decision hits ingest_log.jsonl; every dream, skip and LLM error hits history.jsonl with a timestamp.

✓ dream.py history
03

Compare with an eval

compare() diffs consecutive dreams; losing any entry with importance ≥ 0.7 raises a degradation warning before damage becomes permanent.

✓ 100% retention, 0 lost (runlog §9)
04

Plan to forget

Crystallized memory is capped by importance (default 60). Selective forgetting happens only in layer 2 — episodic is never pruned.

✓ entries_pruned tracked in stats
07 · interactive

Rollback is just a pointer

Because every dream is a separate immutable file, undoing consolidation is O(1): rewrite one line in latest.txt. The episodic layer and both artifacts stay byte-identical.
